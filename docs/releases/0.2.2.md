# Tiny Refuel 0.2.2

- Lokal modelsøgning pr. fabrikant med begrænset antal forslag, valgfri årgang/variant og bevaret manuel indtastning.
- Renset DMR-katalog fra 2026-10-07 begrænset til 895 modeller og 89 mærker i én katalog.json uden variantinventarer med kendt tank-/batteristørrelse. Motorredskaber er udeladt; egne køretøjer kan indtastes manuelt.
- Søgbart mærkevalg med højst 60 forslag, indekserede katalogopslag, manuelt valg af køretøjstype og modelår. Egne mærker/modeller og tekstfallback bevares. Modelårsforslag bekræfter ikke bestemte motorvarianter.
- Udviklerværktøj henter Toyota-modelkandidater til gennemgang før katalogimport.
- Kortets hovedfil hedder nu tiny-refuel-card.js. Det gamle filnavn indlæser den nye fil for eksisterende manuelle ressourcer.
- HACS-validering uden undtagelser, Hassfest og dansk landekode.
- Informations- og fejlfelter bevarer deres åbne tilstand ved dataopdatering.
- Ladeoversigten bliver åben indtil Luk eller en anden ladeoversigt.
- Fordels- og data-API-fejl vises i fejloversigten.
- Ét begrænset genforsøg ved HTTP 500/502/503/504 fra offentlige GET-kilder.
- Detaljeret køstatus for koordinatopslag: konkrete adresser, antal forsøg, resultater, fejl og første mulige genforsøg efter manglende søgeresultat. Adresseopslag omfatter også ladestationer inden for samme fælles budget.
- GitHub-issueudkast med fejlkategorier og HTTP-koder, som brugeren selv indsender.

Efter opdatering: genstart Home Assistant og genindlæs browseren.

- Logopulje til 281 mærkenavne: 261 SVG og 20 PNG. 16 SVG’er er visuelt gennemgåede rastersporingsresultater med bevarede kildeoplysninger. Leapmotor, NIO, Zeekr og NAVOR er indlejret som SVG; NAVOR kræver ikke længere et eksternt billedkald. Det ændrer ikke det medfølgende modeludvalg.

- Kataloget leveres som én almindelig katalog.json med fælles hentning for kort og editor. Alle eksisterende logoer bevares. Eget katalog kan angives med katalog_url og kontrolleres med validate_vehicle_catalog.py.

- Kompakt katalog med kapacitetsfiltreret udvalg og bevarede logoer; ingen ekstra katalogdele hentes. 99 modelrækker med gentaget mærke er samlet med eksisterende modeller, og otte symbolbetegnelser er fjernet. Gamle modelnavne virker som søgealiaser.

- Frivillig kompakt visning: mindre afstande, færre oversigter, skjult køretøjsvælger ved ét køretøj og skjult Hent data-knap som standard. Flere køretøjer bevarer altid vælgeren.
- Konfigurerbart antal rækker pr. brændstof-/eloversigt (0–50, 0 = alle), standard tre i kompakt visning. Vis 10 mere udvider hver liste særskilt; alle data og ladeoversigtens filtre bevares.

- Clever: ét genforsøg ved ugyldigt JSON eller afbrudt HTTP-svar bruger en unik forespørgselsadresse, no-cache-headere, ukomprimeret svar og længere timeout. Gemte ladesteder bevares fortsat ved fejl; delvise JSON-data accepteres ikke.
- Fejlfeltet forklarer JSON-fejl særskilt. HTTP 500-forklaringen vises kun, når en HTTP 500-fejl faktisk forekommer.

- Brugerrettede tekster bruger køretøj/køretøjer: overskrifter, standardnavne, tilføj/fjern, filtre, værktøjstips og vejledning. Eksisterende YAML-nøgler og selvvalgte navne bevares.

- Skift af mærke/model rydder gamle afhængige felter og tidligere genererede navne; egne navne bevares. Årgang filtrerer verificerede variant-årgangskoblinger. DMR-importen bevarer nu modelår pr. variant ved fremtidig import. Eksisterende modeller uden koblingen kræver manuelt variantvalg.
- Kompakt visning viser billigste brændstofpris. Vis færre gendanner kortets rækkegrænse og ladepopup'ens ti rækker.
- Selvstændigt Python-script til mangelliste og kildebaseret indsamling af specifikationskandidater; gennemgang kræves før import. Se docs/vehicle-spec-scraper.md.

- Årgang/variant ligger i et valgfrit sammenklappeligt afsnit. Katalogfeltet viser den faktisk indlæste kilde og beskriver det indbyggede katalog korrekt. Ugyldigt eget katalog giver synlig fejl og bevarer manuel indtastning.
- Ingen skjult afkortning af tanke til 5–200 L eller batterier til 10–200 kWh. Diesel understøttes i fuld-tank-beregningen; plug-in-hybrid kan vise både tank og batteri. Små positive decimalværdier accepteres.
- Knapnavn Hent alle data og versioner/henvisninger er ensrettet. Eksisterende entity-ID'er og YAML-felter bevares.

- GitHub-workflow med rigtig Home Assistant 2026.10 og Chromium: 49 screenshots i mobil-/desktopbredde og lyst/mørkt tema. Kontrollerer blandt andet mærke-/modelskift, katalogkapacitet og Vis 10 mere/Vis færre. Nye billeder i README og separat vejledning til genkørsel.
- Den gamle ladevejledning om et separat scraperscript er erstattet af integrationens Hent alle data.

- Årgang som manuel metadata bevarer drivmiddel og kapacitet, medmindre en verificeret årgangskobling ændrer den valgte variant.
- Navigation til brændstofstationer uden koordinater bruger den kendte adresse.
- Delvise brændstofhentninger bevarer eloversigten uden dubletter; udeladte stationer genindsætter kun fravalgte drivmidlers priser. Gemte lokale ladepriser bevarer kilde og fejlmarkering.
- Monokrome køretøjslogoer vises hvide i mørkt tema og sorte i lyst tema; farvelogoer bevarer deres farver.

- Sensorer for billigste og gennemsnitlige lokale benzin-, diesel- og elpriser, brændstofstationer, fejl og manglende koordinater. Valgfrie sensorer viser selskabspriser, generelle ladetakster og kildestatus.
- Binære sensorer for igangværende hentning og datakildefejl samt separate henteknapper for benzin, diesel og el. Eksisterende sensor- og knapidentiteter bevares.
- Fælles køretøjer oprettes, redigeres og fjernes via integrationens Konfigurer-menu. De giver station-, afstand-, pris- og kapacitetssensorer og bruges af kort uden egne køretøjer. Lokale kortkonfigurationer har fortsat prioritet.
- Offentlige ladetakster bevares med oprindelig hentetid og fejlmarkering ved kildefejl; nye prissensorer bruger kun aktuelle lokale priser.
- Ingen skjult 50-liters antagelse: fuld tank kræver en kendt kapacitet eller gyldig tanksensor.
- Kompatibilitetstest for minimum Home Assistant 2025.11.2 og den aktuelle testversion 2026.10.0. Browsertesten omfatter automatisk modulindlæsning og gemning/genåbning gennem Lovelaces egen editor.
